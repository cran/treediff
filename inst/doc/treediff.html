Introduction

treediff tests whether two families of trees (hierarchical clusterings) have the same structure. The test is based on the cophenetic distances of the trees and on aggregated Student’s tests, with moderated variances (Neuvial et al., 2024).

treediff is a general purpose test for trees but has been initially designed to compare 3D genomic structure based on Hi-C data. In this context, trees are obtained using adjacency-constrained clustering of Hi-C contact maps along the genome (as implemented in Ambroise et al., 2019), where several maps from two conditions are available.

This vignette illustrates the main features of the package on a small Hi-C data set, stored in the extdata directory of the hicream package:

  • the wrapper HiC2Tree(), which goes from Hi-C files to test results in a single call;
  • the step by step pipeline (HiCDataSet(), normalizeCount(), clusterTree(), and treediff());
  • the exploration of the results (print() and summary() methods and link with genomic coordinates).
library("treediff")

The pighic dataset

The pighic dataset is an extract of the dataset published in (Marti-Marimon et al., 2021). It contains 6 Hi-C matrices (3 in each condition) obtained from two different developmental stages of pig embryos (90 and 110 days of gestation) for two chromosomes (1 and 2). Hi-C contact maps are provided in HiC-Pro format and an additional file (the index) gives the genomic coordinates of the bins.

replicates <- 1:3
conditions <- c("90", "110")
chromosomes <- 1:2

all_begins <- as.character(interaction(expand.grid(replicates, conditions),
                                       sep = "-"))
allMat <- lapply(chromosomes, function(chr) {
  paste0("Rep", all_begins, "-chr", chr, "_200000.bed")
})

files <- system.file("extdata", unlist(allMat), package = "hicream")
index <- system.file("extdata", "index.200000.longest18chr.abs.bed",
                     package = "hicream")
format <- rep("HiC-Pro", length(files))
binsize <- 200000
nb_replicates <- c(3, 3)
basename(files)
#>  [1] "Rep1-90-chr1_200000.bed"  "Rep2-90-chr1_200000.bed" 
#>  [3] "Rep3-90-chr1_200000.bed"  "Rep1-110-chr1_200000.bed"
#>  [5] "Rep2-110-chr1_200000.bed" "Rep3-110-chr1_200000.bed"
#>  [7] "Rep1-90-chr2_200000.bed"  "Rep2-90-chr2_200000.bed" 
#>  [9] "Rep3-90-chr2_200000.bed"  "Rep1-110-chr2_200000.bed"
#> [11] "Rep2-110-chr2_200000.bed" "Rep3-110-chr2_200000.bed"

Files must be ordered by chromosome, then by condition, then by replicate. The vector nb_replicates gives the number of replicates in each condition (here, 3 in the first condition, 90, and 3 in the second one, 110).

All-in-one analysis with HiC2Tree()

HiC2Tree() reads the files, normalizes the contact counts, builds one tree per matrix and runs the treediff test:

res <- HiC2Tree(files, format, binsize, index, chromosomes, nb_replicates)
names(res)
#> [1] "trees"    "metadata" "index"    "testRes"

The output is a list with four entries:

  • trees: the list of all trees (one for each matrix);
  • metadata: a description of each tree (matrix, chromosome and cluster);
  • index: the genomic coordinates of the bins;
  • testRes: the results of the treediff test.

Build the trees

clusterTree() clusters the bins of each chromosome with a constrained hierarchical clustering (only adjacent bins can be merged, adjclust::adjClust()), cuts the chromosome into clusters using the broken-stick rule and builds one tree for each cluster and each matrix.

Run the test

treediff() takes two lists of trees. Within each list, trees are ordered by cluster and then by replicate. The number of replicates in each condition is given by replicates, and one \(p\)-value is obtained for each cluster.

Here, we first select the trees of each condition (the first 3 trees of each cluster belong to the first condition and the last 3 to the second one) and run the test on all clusters:

nb_clusters <- nrow(unique(clust$metadata[, c("chromosome", "cluster")]))
in_cond1 <- rep(rep(c(TRUE, FALSE), nb_replicates), nb_clusters)
trees1 <- clust$trees[in_cond1]
trees2 <- clust$trees[!in_cond1]

test <- treediff(trees1, trees2, replicates = nb_replicates)
test$p.value
#> [1] 0.2836782 0.0000000

These are the same \(p\)-values as the ones obtained with HiC2Tree():

all.equal(test$p.value, res$testRes$p.value)
#> [1] TRUE

The trees of the second condition may have a different number of replicates than the trees of the first one: It is enough to give the right values in replicates. Two options of treediff() are also useful in practice:

  • scale = TRUE rescales all trees so that their heights range between 0 and 1, which removes global differences in height between the trees. In practice, we do not recommend using this option unless you know what you are doing;
  • order_labels = TRUE aligns the order of the leaves between all trees, which is required when the trees have not been built with the same leaf ordering.
treediff(trees1, trees2, replicates = nb_replicates, scale = TRUE)$p.value
#> [1] 0.5702923 0.3749414

Exploring the results

The p.value.indiv and statistic entries of the output contain the Student’s test of each pair of leaves of the trees (for all clusters). Their distribution can be used to check how the signal is distributed:

hist(test$p.value.indiv, breaks = 50, main = "Individual p-values",
     xlab = "p-value")

The cluster-level \(p\)-values are linked to genomic regions through the metadata and index entries of the HiC2Tree() output. For instance, the genomic span of the bins of each chromosome is:

aggregate(cbind(start, end) ~ seqnames, data = res$index,
          FUN = function(x) c(min = min(x), max = max(x)))
#>   seqnames start.min start.max   end.min   end.max
#> 1        1 224800001 225800001 225000000 226000000
#> 2        2         1 151800001    200000 151935994
